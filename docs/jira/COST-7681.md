## Description

Deliver the resource management layer that all phases use to create, update, and delete Kubernetes resources:* Server-Side Apply (SSA) -- all resources are applied with field manager cost-management-operator, so Kubernetes tracks which fields the operator owns and can detect conflicts with manual edits

- ownerReferences -- every namespace-scoped child resource (Deployments, Services, ConfigMaps, Jobs, etc.) gets an ownerReference to the CostManagement CR, enabling automatic cascading deletion when the CR is removed
- Finalizer-based cleanup -- cluster-scoped resources (ConsoleLink, ClusterRole, ClusterRoleBinding) cannot use ownerReferences; instead, a finalizer on the CR blocks deletion until the operator removes these resources first
- Drift correction -- on every 5-minute periodic requeue, the operator re-applies desired state via SSA, reverting any manual modifications to managed resources

### Out of Scope

- Building any specific application resources (those are delivered in later stories that consume this layer)
