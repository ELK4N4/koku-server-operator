## Description

Deliver the existing pytest suite running against an operator-deployed environment
instead of Helm. Update setup/teardown to use CR lifecycle.

### Acceptance Criteria (refined)

- Operator-only harness lives in this repo (`test/pytest/`, `scripts/deploy-test.sh`, `scripts/run-pytest.sh`)
- Helm-specific suites/helpers removed (no `HELM_*`, no `suites/helm/`)
- Setup/teardown uses `CostManagementServiceConfig` create/delete (`CR_NAME=cost-management`)
- Fixtures use operator naming (`cr_name`, `cost-worker-*`, `cache`, …)
- At least one cluster `deploy-test` / tests-only run attempted; failures classified below
- **Green suite not required** to close if remaining failures are operator bugs after wiring is ruled out

### Out of Scope

- New operator-specific tests (COST-7698)
- OpenShift CI / OLM job wiring (COST-7699)
- Operator product bug fixes (file separately)

### Wiring issues (fix in this story)

- **Keycloak JWKS URL** — RHBK with `httpEnabled: false` black-holes `http://…:8080`. Sample + `deploy-test.sh` now use `https://keycloak.keycloak.svc.cluster.local:8443` and `tls.insecureSkipVerify: true`.
- **Duplicate OperatorGroups in `keycloak`** — `deploy-rhbk.sh` created a second OG → CSV Failed (`multiple operatorgroups`). Script now creates an OG only when the namespace has none.
- **Ingress image missing in pytest CMSC sample** — empty `spec.ingress.image` → pod `InvalidImageName` (`:`). Sample now sets `quay.io/iop/ingress:master` (chart default).
- **`test/pytest/` name collides with pytest package** — default import mode loads root conftest as `pytest.conftest`. Fixed via `--import-mode=importlib` in `pytest.ini`; hardened `run-pytest.sh` venv (`--copies`, `python -m pytest`).
- **Keycloak password grant `Account is not fully set up`** — dominates ERRORs (~40+ setup failures for `admin` / lab users). Realm users need required-actions cleared / email verified (chart RHBK bootstrap does this; operator harness path incomplete). Follow-up: align `deploy-rhbk.sh` / test bootstrap with chart user setup.
- **UI pod Pending / image pull** — UI OAuth container failed to pull; `--no-ui` still hit one UI-pod health assert in auth suite.
- **Cleanup `database "koku" does not exist`** — teardown psql targets wrong DB name vs operator bundled Postgres.

### Operator bugs (do not weaken assertions; track separately)

- **Kruize ClusterRole escalation** — controller could not create `*-kruize-*` ClusterRole because manager-role lacked the verbs it grants (`pods`/`nodes`/`endpoints`/`daemonsets`/`replicasets`, `metrics.k8s.io`, `custom.metrics.k8s.io`). **Operator product bug** — track/fix separately; not in COST-7697 test harness scope.
- **Ingress/gateway `Jwt issuer is not configured`** — authenticated upload and several ROS/gateway calls return **401** with that message (~9+ fails). Operator ingress JWT issuer wiring incomplete vs chart.
- **Cascades** — e2e upload→manifest→kruize / “Could not get OpenShift source type ID” largely follow auth/issuer failures above.
